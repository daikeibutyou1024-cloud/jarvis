# BTC/JPY公開チャート・画面内通知（Preview限定）

## 操作

HOMEでオーブ下の時計領域をチャートに変更した。時計自体はチャート下部に残す。「相場データを取得」または期間変更が取得のきっかけであり、ページ表示・再読み込みだけでは取得しない。マイク・FINANCEの既存架空資産報告は従来どおり。

1日＝1時間足、1週間/1か月＝4時間足、3か月/6か月/1年＝日足。期間は24時間/7日/30日/90日/180日/365日の移動窓。ローソク足、MA20（黄）、MA50（青）、出来高を表示する。スマホでは横スクロールと「足の詳細」スライダーで確認できる。日付・取得時刻は日本時間表示、取得パーティションと内部計算はUTC。

## 公開データのみ

`GET /api/business/bitbank-market-preview?period=year`（day/week/month/quarter/half/yearのみ）を使用する。Previewホスト・ブランチ・署名セッションを検証し、Productionや書き込みメソッド、任意URL指定を拒否する。D1・秘密キー・Claude APIは使わない。

公式資料： https://github.com/bitbankinc/bitbank-api-docs/blob/master/public-api.md

外部取得先は `https://public.bitbank.cc/btc_jpy/candlestick/{type}/{date}` の固定GETだけ。1時間足はYYYYMMDD、4時間足/日足はYYYY。計算用60本を表示期間の前から取得するため、1年表示が暦年をまたぐ際は最大3年分のパーティションを結合する。日付パーティションは最大5件。年途中で切らず、同時刻重複を排除し、不一致は拒否する。

ユーザーのCookie、bitbank秘密APIキー、既存APIキーを外部へ転送しない。redirectは禁止。取得全体10秒、1応答2MB、元データ10000件・採用後600本以下、任意足や任意ペアには非対応。失敗・429・形式不正時に再試行しない。公開レスポンスを最大60秒キャッシュできるが、ユーザー向け応答はno-storeとし取得時刻を表示する。追加契約・定期実行はない。

この開発環境からpublic.bitbank.ccへの直接HTTPはプロキシ403で拒否された。実APIを模擬データへ置き換えて本番表示するfallbackはない。ローカルの模擬テストと実接続確認を区別し、Previewで「相場データを取得」が成功するまでは実データ接続を未検証とする。取得できなければ判定保留になる。

## 分析と未来情報の除外

- 開始時刻＋足の長さが判定時刻以下の確定足だけ採用する。表示期間以前の計算用データを含むが、未来・未確定足は指標へ渡さない。
- 単純移動平均20/50、Wilder RSI14、直前20本の平均出来高に対する出来高比、直前20本の高値/安値、直前足比・表示期間比を計算する。出来高・高安の参照窓から現在の足を除外する。
- 購入検討：MA20≧MA50、価格≧MA50かつ価格≦MA20×1.02、RSI35〜60、出来高比≧0.8。
- 警戒：価格＜MA50かつMA20＜MA50、またはRSI≧75、または直前確定足比が−5%以下。警戒を先に評価する。
- 上記以外は様子見。連続確定足60本未満、表示期間の欠損、計算用区間の欠損、出来高不足、指定期間の不足、最新の確定時刻から2本分を超える遅れは保留。
- 分類はルールベースの参考情報であり、注文や価格予測ではない。根拠と反対のシナリオを併記し、値上がり・利益を保証しない。

履歴検証は表示期間内の各時点までの指標だけを使い、その時点の分類数を集計する。購入検討の次の確定足が上昇したかは事後比較の集計にだけ使用し、判定へ戻さない。未来データを差し替えても過去の判定が変わらないことをテストする。売買執行、取得原価、手数料、スリッページを含まず、収益性の証明やパラメータ最適化ではない。

## 通知候補

初期状態は無効。ユーザーが分類、RSI上限、任意の価格上限、出来高比下限を保存し、次回の手動取得時だけ評価する。全部の条件を満たした場合だけ画面内の通知候補を生成する。保留・取得失敗時には生成しない。

新しいlocalStorageキー `jarvis_bitbank_market_alerts_v1` に条件と候補履歴を保存する。判定時刻、条件設定時刻、確定足の終了時刻、時間足・分類・価格・RSI・出来高比・根拠を記録する。pair＋時間足＋確定足の終了時刻＋条件を重複キーとし、同じ足への重複候補を拒否する。Web Locksで同一ブラウザ複数タブの読取・保存を直列化する。Web Locks非対応・保存失敗時は通知記録を停止し、外部通知へfallbackしない。

履歴は最大100件、画面には最新10件。上限時は自動削除せず追加を停止する。条件保存・既存履歴の形式が不正なら上書きしない。端末/ブラウザ間の同期・重複排除は行わない。新規キー以外のlocalStorageや保存データ、D1、バックアップを変更しない。

OS通知、メール、SNS、Webhook、Cron、自動取引、バックグラウンド更新はない。これらの追加には別途明示承認が必要。

## 安全性・復旧

Production環境変数・main・本番DBを変更しない。既存のbitbank架空資産・音声・天気・認証・保存機能を維持する。今回の追加にSecret設定やDB移行は不要。問題時は新規チャートの手動取得と通知候補を停止して既存機能を使える。Previewコードを戻す場合も既存データ・新しい端末内履歴は削除しない。
