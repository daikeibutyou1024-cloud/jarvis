# note有料記事の制作

対象形式は「note有料記事」。無料記事・比較記事・他部門の既存経路は維持する。

## 制作手順

1. RESEARCHで確認した資料をCONTENTへ渡す。本文取得と利用者確認は別の状態で、AIへ渡す本文は従来どおり先頭最大700文字。R番号、元資料ID、URL、取得・本文取得日時、利用者確認、提供範囲を保存する。
2. 全体を作成するか、章を順に選ぶ。章名の候補は「無料部分」「有料部分」「実践手順」「記入済みサンプル（架空の例）」「完成テンプレート」。無料・有料は第二階層、成果物は有料部分の第三階層。章生成は章本文だけの専用指示で、見出しはアプリが付ける。
3. 中断した章は「続きを作成」。新しい章の追加と途中からの継続を分離する。両方に既存原稿との重複・逆戻り検査を実行し、不適切な応答は結合しない。
4. 不足欄を見て補完する。実践手順は準備・入力・操作・出力・確認・失敗時、架空の記入済み例は入力例・出力例、完成テンプレートは入力欄付きコピー用コードブロックと使い方が必要。販売予定の紹介だけでは不足となる。
5. 出力上限で止まった場合は未完成を保持する。手で全文を補完した場合のみ「全文の補完完了を確認」を使う。必須内容が欠けていれば解除されない。
6. 形式検査を通っても内容の実用性・正確性・引用の妥当性は保証しない。全文・根拠・架空例の表示・個人情報・権利を人間が確認し、明示的に「確認済みにする」。公開・販売・外部投稿は行わない。
7. 端末保存、または「有料原稿をクラウド保存（AI利用なし）」で原稿・制作条件・章・成果物・資料・生成状態・人間確認を保存する。通常のクラウド生成にも制作メタデータを保存する。保存済み原稿はクラウド一覧から開く。

## 保存と互換性

生成メタデータ内の `project` に記事ID・構造化した章本文・成果物検査・資料スナップショット・生成状態・人間確認を保存する。専用保存は認証された `/api/business/paid-drafts` を利用し、独立した `paid_content_drafts` テーブルを初回に追加作成する。既存テーブル・制約は変更しない。保存時はサーバーでも成果物を再検査し、クライアントの不足一覧を信用しない。AI APIやAI利用枠を使わず、原稿ID単位で更新する。端末保存は従来の下書き形式に追加メタデータを保持する。

既存の下書きは削除・一括移行しない。有料形式の旧原稿を開くと再検査し、以前の確認済み状態を自動継承しない。元本文を勝手に削除しない。資料付録を取り除いた本文と管理データから出典一覧を構成し、出力や保存の繰り返しで一覧を重複させない。

全体10回/日、クラウド生成5回/日（UTC、失敗含む）、Claude出力4000/2500トークンを変更しない。追加の有料サービス・自動再試行・自動連続生成はない。原稿30000文字、資料3500文字の既存AI入力制限を維持し、超過時は自動切捨てせず拒否する。長文の無制限な章再開は今後の課題。

## 限界

機械検査は固定構造・明示的な不足・未知の出典番号・未登録URLの検出であり、意味上の品質・主張の真偽・引用との整合・言い換え重複・商業価値を保証しない。偽の実績を禁止する指示を含めるが、実績の真偽判定には人間の確認が必要。出典がない場合は未取得と明示する。外部情報を事実として使う際は資料を取得・確認する必要がある。

実Claude APIを呼ばない単体・ブラウザ回帰テストを用意する。実モデルの生成品質、本番D1の実データ、実APIを使ったPreview生成は未検証とする。

## 不足章の追加・補完（章生成の検査修正）

章追加では、別章にある「入力例」など第四階層以下の小見出しの再利用を許す。記事タイトル・無料/有料部分・成果物の章見出し・既存章本文の再生成は引き続き拒否する。続き生成では小見出し再利用の緩和を行わない。生成応答の先頭に対象章の見出しが一度だけ含まれた場合は取り除き、アプリが一つに統一する。二度目の対象章見出しは拒否する。

既存の対象章が不足している場合は、その章の末尾・次の章の直前に追記し、古い本文や「未取得」の欄も削除しない。項目の充足検査は同じ欄の最後の記入値を用いる。既に成果物が充足した章の章生成は事前に停止する。章構造が重複・曖昧な場合も停止し、利用者へ確認を促す。存在しない成果物を追加するには、一つの有料部分が先に必要。

章の途中停止からの続きは、保存した対象章名を使い、後続章の前に追加する。対象章末尾と原稿全体の両方で重複を検査する。失敗した応答は結合せず、人間の確認状態も変更しない。成功した追記は人間の確認を解除する。専用クラウド保存も対象章名を保持する。事前に検出できる不正な章操作はAPI呼び出し・利用枠予約の前に拒否する。APIに到達した生成失敗は従来どおり利用枠を消費し、自動再試行しない。

追加の制作案件・長文の保存版再開・版にひも付く全文確認と原稿出力は [EDITORIAL_WORKFLOW.md](EDITORIAL_WORKFLOW.md) を参照。旧端末の確認フラグとは別の記録を使用する。
