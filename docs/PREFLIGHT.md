# 運用開始前の確認

前回の残課題であるPreview・D1・費用・定期起動の実設定確認に向けて、認証付きの読取専用診断を追加した。設定の有効化、起動元の配備、課金APIの使用、データ移行や修復は行っていない。

## 操作

司令室の「運用開始前の確認」→「設定・開始条件を確認（実行なし）」を押す。既存のアクセス認証を使用する。画面を開くだけでは要求しない。APIはGET /api/business/preflight。応答はno-store。POST・任意SQL・任意URL・自動再試行の機能はない。

認証後にD1の読取が発生する。今回リモートでこの操作は行っていない。実環境で利用する前にCloudflareの利用枠・追加課金の有無を確認する。パスワードやAPIキーをチャットへ貼り付けない。

## 確認できること

- CF_PAGES_BRANCHが開発ブランチの申告値か。値そのものやURL・DB識別子は返さない。未設定は不明として扱う。
- business_jobs、document_revisions、editorial_reviews、ai_operations、collection_schedules、collection_runs、research_inbox、business_records、business_record_history、business_imports、business_write_guardsの必須列の存在。PRAGMA table_infoのみで確認し、未作成のテーブルを作らない。旧Google・paid_content_drafts・調査キャッシュ等の全テーブルを対象にした移行検証ではない。型・制約・索引・ユーザーデータの内容・書込権限・復元も未検証。
- AIの設定形式は実行処理と同じaiConfigを再利用する。選択中providerのキー・予算・料金・開始利用額の形式を確認するが、キー・モデル文字列・料金JSON・例外原文を返さない。実APIへ接続しない。
- AI台帳が読める場合、UTC対象月の管理値・予約、開始利用額を含む管理上の残枠、予算超過・前月未確定・超過利用による停止条件、期限超過のrunning件数。実請求ではなく、残枠があっても次回の原稿が予算内で生成できる保証はない。
- 定期収集の全体停止・専用認証・日次上限、現在の対象時刻の設定数、実行中/期限超過、UTC日の試行数、受信箱容量。期限超過ジョブの更新・予約・日時繰越・外部取得をしない。

eligible_snapshotは「現時点で開始条件の見込みあり」であり、稼働確認や開始許可を意味しない。共有取得制限、起動元の秘密一致、外部通信、実行時の再判定や同時更新の結果は未確認。複数の読取は同一時点を保証しない。確認時刻を表示し、失敗時は前回の結果を現在の状態として残さない。

## 本番判断の扱い

APIのproductionReadyは常にfalse。本機能だけでは実データの安全性や主要機能の完成を判断できないため、次は以下を別途検証する。

1. PreviewとProductionのD1分離、実アカウントの費用設定を確認する。
2. 既存データを含むバックアップ・復元手順を確認する。完全バックアップの取得やバックアップブランチの変更は今回行っていない。
3. Previewで認証後の保存・再取得・競合・移行を検証する。
4. 無料枠と権限が確認できた後に、定期起動の配備と実際の稼働を検証する。
5. 外部公開・販売・成果取得の必要なアカウント/権限と連携方式を決める。外部投稿の実行は別途明示承認が必要。

## テスト結果

ネットワーク遮断下の模擬SQLite/D1とDOMで10件追加、全169件成功。DB前後比較・書込禁止ラッパーにより、期限超過ジョブや未作成スキーマを変更しないこと、認証拒否、秘密と例外の非開示、予算停止、収集容量/試行上限、無要求の初期表示、二重要求防止、取得失敗時の古い結果消去を検証した。

既存のPlaywrightテストはChromium起動時のsocket() Operation not permittedにより本体未実行。実Previewの認証後の診断・DB読取を確認した結果ではない。実Claude API、実OpenAI API、実収集を呼ばずに検証した。
