# 保存・費用管理の安定化

対象は feature/ai-business-rebuild。main・Production・バックアップの変更、実AI APIの検証、リモートD1への移行は行わない。

## 案件と原稿の版

- 案件IDは UUID（旧原稿の既存IDも使用可）。全形式のAIを使わないクラウド保存を追加。
- `document_revisions` の `(project_id, revision)` ごとに原稿・資料・生成メタデータのスナップショットを保存する。通常は版1から開始。過去の版は更新しない。
- クラウド一覧と「開いている案件の版履歴」から再読込できる。履歴は最新100版を表示し、DB上の古い版を削除しない。過去の版を開いて保存しても最新版の上書きはできない。
- 保存する版番号 `expectedRevision` とDBの最大版を、同じINSERT文で比較する。競合時は409 `SAVE_CONFLICT`。自動上書き・自動再試行をしない。入力中の本文は画面に残す。端末保存またはコピー後に最新版を開く。
- 有料原稿の既存テーブルへの反映と版追加、クラウド生成のジョブ反映と版追加はD1のatomic batchで行う。途中失敗時は一括ロールバック。
- 生成前にも版を確認する。生成中に別の保存が完了した場合は上書きを拒否し、生成応答を409の `recovery` として返し画面に保持する。そこで本文を端末保存してから最新版を確認する。競合で返った応答を自動再生成しない。
- 全体生成は新案件。章・続き生成は同じ案件を使用。生成そのものと「確認済み」は引き続き別状態。
- 端末保存は従来のlocalStorageキーを使用し、案件ID・端末版・クラウド版を追加。Web Locksで同一ブラウザのタブ間保存を直列化し、古い端末版の保存を拒否する。Web Locks非対応では安全のため端末保存を停止し、コピー／クラウド保存を案内する。
- 旧端末原稿はそのまま読める。初回保存時に新しい識別情報を付ける。30件での自動切り捨てを廃止し、容量超過では保存失敗を表示する。端末版の削除は利用者の明示操作のみ。
- 旧有料原稿は再読込時にクラウド版0として扱う。更新には `expectedRevision:0` が必要で、更新前の本文を版0に保全する。版指定のない旧クライアントによる既存原稿の更新は409で停止。旧business_jobsの本文は変更せず読み込める。
- 既存テーブルのALTER/DROP、データ一括移行は行わない。追加テーブルは認証付き操作時に作成。`0005_stability.sql` は同じ定義の手動適用用で、本開発ではリモート適用しない。

## 共通AI経路

通常相談・通常原稿・クラウド原稿・企画を `lib/ai-runtime.js` に集約。OpenAI切替も共通。旧GitHub Actionsの直接Claude呼び出しを削除し、開発ブランチのオフラインテスト専用に変更する。定期実行やAPI自動実行は追加しない。

既存のUTC日次回数制限（全体10回、企画2回、クラウド5回）を維持。課金要求を試みた失敗や出力検証失敗の枠は戻さない。予算／設定の拒否は課金を行わず、予算の未使用予約は取り消す。既存business_jobsの5件枠は従来どおり試行件数で制限する。

## 月額予算の設定

Cloudflare Previewの環境変数で次を設定する。**未設定・不正値・未登録モデルはAI利用を停止する**。保存・履歴取得・手入力集計は引き続き可能。

| 変数 | 内容 |
|---|---|
| `AI_MONTHLY_BUDGET_USD` | USDの月額上限。正の数を文字列で指定。小数6桁まで。実際の予算は利用者が決める |
| `AI_PRICING_JSON` | `{"provider/model":{"input":料金,"output":料金}}`。料金は100万トークン当たりUSDの正の数。モデル名完全一致 |
| `AI_OPENING_SPEND_USD_JSON` | 任意。`{"YYYY-MM":"開始時点の既利用額USD"}`。未設定は0。この台帳開始前の当月利用を予算へ含めるために使う |
| `AI_TIMEOUT_MS` | 任意。既定30000、上限60000。テストでは短縮できる |

料金の例は構造だけを示す。`{"anthropic/利用モデル":{"input":公式で確認した料金,"output":公式で確認した料金}}`。これはそのまま貼るJSONではない。最新の実料金を確認して数値を設定し、モデル変更時にも更新する。コードに料金の推測値や既定予算は入れない。設定値をフロントから変更するAPIは提供しない。

この開発では環境変数を設定せず、有料契約をしない。PreviewでAIを再開する前に設定が必要。

### 金額の扱い

- USDの100万分の1を整数で保持。UTC月単位。
- 送信テキストのUTF-8バイト数＋プロトコル余裕1024と、出力トークン上限（4000／2500／3200）から保守的な予約額を計算する。両プロバイダーで出力上限を明示。
- D1の1つのINSERTで、開始時点の利用額＋同月の記録・予約合計＋今回予約額が予算以内かを判定。同時実行も予約を含む。
- トークン利用が完全に取得できた通常応答では設定単価で再計算。キャッシュ利用やusage欠落などで算定できない場合は予約額を保持する。
- HTTPエラー、タイムアウト、通信切断は課金が不明なため全額予約を残す。APIへ未送信の回数上限拒否等は予約を0へ戻す。
- 予約より多い利用が返った場合は `overrun` を記録し、確認まで追加のAI実行を停止する。前月から課金未確定の処理が残る場合も確認まで停止する。
- 「AI予算・実行履歴を取得」で記録を表示。未確定・中断・超過は、利用者がプロバイダーの請求を調べ、確認額USD・メモ・確認チェックを入力して照合できる。照合操作は再試行や日次枠の返還を行わない。照合済みの同じ記録を再度変更しない。
- **請求実額の自動取得ではない**。このアプリから設定単価で計測した管理値であり、税・為替・他アプリの同じキーの利用・導入前の利用・料金変更は自動で把握しない。導入前の利用は開始額に計上する。誤った料金設定で請求額の上限を保証することはできない。プロバイダー側の利用上限と併用する。

## タイムアウトと中断

- AIのfetch開始からJSON本文の受信までを共通タイマーで制限。AbortとPromise.raceを併用し、応答しない模擬通信でも終了する。遅れて返った応答は採用しない。自動再試行はない。
- `ai_operations` に目的、モデル、ジョブID、開始／期限／終了、状態、設定単価、予約額、利用トークンを保存。プロンプト・認証秘密は入れない。
- 実行期限を過ぎたrunningをinterruptedへ変更。古いbusiness_jobsのrunning（120秒超または関連実行が中断）は、既存status制約に合わせてfailedとし、中断の理由を付ける。
- 整理は認証済みのAI実行・履歴／ジョブ取得時に行う。ブラウザを閉じた直後に常駐処理が走るわけではない。
- ブラウザのAPI通信も75秒で停止。保存応答を受け取れなかった場合は既に保存済みの可能性があるため、再クリック前に一覧を取得する。古い版の再送は競合で保護される。
