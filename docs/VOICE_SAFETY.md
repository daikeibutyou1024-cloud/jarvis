# Preview音声会話・iPhoneの検証範囲

実Claude/OpenAIは停止したまま。モック回答は画面で明示し、読み上げでも「プレビューのモック回答です」と案内する。オーブはPreviewモック会話、入力欄の◎は文字起こし専用。どちらも `voice-input.js` の同じ認識エンジンを使い、同時に複数のマイクを開始しない。会話だけが、確定結果を約3秒後に一度送信する。途中結果のみ・空・認識エラーは送らない。音声会話の認証・送信・TTS・次の待機は `voice-session.js` が順番に進め、停止や認証/API/読み上げエラーで自動再試行しない。

認識途中の文字は入力欄に表示し、確定文も保持する。次の会話発話が来た時は新しい文を表示し、既存の会話ログには以前の発話・モック回答を残す。手動入力で編集中の文は上書きせず、先に送信・退避を案内する。文字起こしモードは既存入力に追記し、自動送信しない。

無音の判断はWeb Speechの結果・発話終了イベントを利用する約3秒の判定。音声波形の直接解析や別のgetUserMediaマイクは追加しない。Safariが先に認識終了を通知した場合、会話では残りの時間を待って確定結果だけを送る。結果が途中のままなら停止して文章を保持する。端末/OS/認識サービスによる遅延や終了時刻の差は実機で確認が必要。

## 起動の挨拶

既存の日本語挨拶をSpeechSynthesisで一度試す。onstartが来ない場合は4秒で試行を停止し、「J.A.R.V.I.S.を起動」ボタンを表示する。拒否/例外/非対応でも代替表示を出す。再試行は明示タップ時だけ。空音声・無音再生・自動アンロックループは使わない。同時/完了後の二重挨拶は抑止する。

起動ボタンは最初にマイクを停止し、そのタップ内で挨拶の再生を要求する。「挨拶後に音声会話を開始」を選んだ場合のみ、挨拶終了後に会話開始を試す。認証や非同期TTS後にSafariがマイクの再開を許可しなければ、オーブ再タップで再開する。画面非表示・pagehide時はマイクと読み上げを停止する。ページ再読込で会話を自動開始しない。

音声認識はブラウザ提供元へ音声を送信する場合がある。SpeechSynthesisは端末/ブラウザの日本語音声を利用し、挨拶や読み上げのためにClaude/OpenAIへ要求しない。iPhone実機・実マイク・実音声再生は、模擬Chromiumテストとは別の確認事項。

## 実AIの現在の停止

`lib/ai-runtime.js` の `requireVerifiedLiveBudget()` は送信・DB予約の前に例外で拒否し、フラグでは解除できない。`/api/chat` も認証後に停止応答を返す。今回変更しない。音声会話のUIはPreviewモック選択が無効なら開始/送信を拒否し、Productionではモック会話を使用しない。APIキー・認証・環境変数は変更しない。

## 将来の有効化に必要な費用・安全確認（今回は実施しない）

1. 利用者がAnthropic/OpenAIの管理画面で、実残高、有効期限、自動チャージ/支払設定、直近・未確定利用、他アプリ/他キーからの利用を確認する。今回これらは未確認。
2. 対象provider/modelと公式の最新input/output単価、利用可能モデルを照合する。既存コードは `AI_PROVIDER`（既定anthropic）、モデル指定、`AI_PRICING_JSON` を使用するが、設定値が現在の契約・料金と一致する保証はない。
3. 上限の金額・対象期間・対象アカウント・他経路の支出を含めるかを明示承認する。既存 `AI_MONTHLY_BUDGET_USD` は月次台帳（コード上最大5 USD）であり、総API支出5 USDの保証ではない。開始済み利用は `AI_OPENING_SPEND_USD_JSON` とprovider利用状況を照合する。推測で残高や利用額を埋めない。
4. 事前予約、実使用量の照合、同時要求、タイムアウト後のuncertain、overrun、月跨ぎ未確定利用、日次回数制限と手動停止を模擬テストする。未確定を自動でゼロ精算せず、自動再送しない。
5. サーバーの無条件停止を変更するには、別途明示承認、費用制御のレビュー、新しい候補commitと再テストが必要。環境フラグだけで解除しない。最初の実API要求自体にも、対象環境・モデル・最大費用を含む承認が必要。
6. Production反映、定期実行、自動収集、外部投稿の有効化は今回の音声改善とは別の承認事項。

Googleカレンダーの旧コードとデータは保持する。初期版の既存の非表示・停止状態を、この作業で変更しない。天気・5部門・保存/承認/版管理・認証は従来の処理を再利用する。
