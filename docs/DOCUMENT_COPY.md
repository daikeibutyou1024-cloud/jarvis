# 保存版から別案件として再開

前回まで版履歴の閲覧と競合拒否はあったが、過去版を最新の案件へ上書きせずに再利用する保存経路が不足していた。今回、指定した保存版を別案件の版1として複製する機能を追加した。元の案件・履歴・確認記録・公開記録・台帳を変更しない。バックアップブランチやProductionは操作しない。

## 操作

1. 制作ライブラリで原稿を開き、「開いている案件の版履歴」から必要な版を開く。
2. 「保存版から別案件として再開」を展開し、「開いている案件・版を確認」を押す。元の案件ID・版・保存日時と、本文・資料・制作条件を確認する。
3. 内容確認にチェックし、「確認した保存版を別案件へ複製」を押す。別の案件IDで版1として保存する。
4. 編集中の作業を保存したうえで「複製した案件を開く」を押す。必要な修正を行い、新しい版の全文を確認する。

対象はクラウドの保存済みの版。プレビュー後に入力した内容や端末だけの下書きは含まない。画面を切り替えても、プレビューで確認した案件・版を複製する。別の版を選ぶ場合はプレビューし直す。複製先IDは同じプレビューの間保持し、通信応答が不明な場合も同じIDで明示再送する。自動再試行はしない。

複製成功時にも編集画面を自動で上書きしない。別案件を開く前に未保存の編集があれば既存の保護で停止する。画面を閉じた後も、複製先は通常のクラウド一覧に保存されている。

## 保存と確認の扱い

- プレビューで本文や資料を書き換える機能はない。サーバーに保存された内容のハッシュを照合し、複製時もサーバーから同じ版を読む。要求に任意の本文やapprovedを送っても採用しない。
- 元の全版を保持し、複製元の案件ID・版・ハッシュをcopiedFromとして記録する。複製はDBの完全復元やバックアップではない。
- 新しい案件は版1。元の全文確認や公開の承認を引き継がない。元の確認記録は元案件に残る。
- 本文・資料・企画・構成・制作条件を保持する。有料原稿は本文をそのまま保持し、構造検査と人間の確認待ち状態を再計算する。AI利用メタデータの一部は既存の有料原稿検査の形式に正規化される。
- 旧形式で資料・対象読者・注意事項が存在しない場合は空欄とし、根拠や確認済み状態を補わない。未完成の記事も複製できるが、完成や公開可能とは判定しない。
- 収益・公開URL・AI利用台帳の行を複製しない。過去の生成料金を新たなAPI利用として登録しない。
- 既存の複製先ID・旧形式の有料原稿ID・版0を上書きしない。同じIDと内容の再送は既存の版1を返す。複製先が編集された後の再送は409で止める。
- 版保存と有料原稿の互換ミラーを同じトランザクションにし、一方が失敗したら新規保存も戻す。元の版がプレビュー後に不正に変更された場合や複製先が同時に作られた場合も保存条件で止める。元案件に別の新しい版が追加されても、選択した古い版は変わらないので複製可能。

## API

POST /api/business/document-copy。既存のアクセス用認証が必要、応答はno-store。プレビューと複製を明示する。

- action=preview: sourceProjectId、sourceRevision。保存済みの正確な版とハッシュを返す。スキーマ初期化・旧データの取り込みはしない。
- action=copy: sourceProjectId、sourceRevision、preparedDigest、targetProjectId、confirmed=true。元と異なるIDのみ。必要な既存形式のテーブル初期化以外に、ALTER・削除・一括移行はない。

元の保存内容が不正・未対応・上限超過の場合は停止する。外部アカウント・AI API・定期収集を呼ばない。
