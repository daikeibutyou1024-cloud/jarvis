# Preview通常会話（実送信は別途承認）

対象は feature/ai-business-rebuild / jarvis-preview のみ。Production、一般の `/api/chat`、記事生成、Threadsの動作・承認方式は変更しない。

## 実装と上限

- `/api/business/chat-claude-preview` は署名セッション、同一Origin、Previewホスト、DB識別行、用途別の期限付き承認を検証する。GETは状態取得だけで、モデルAPIを呼ばない。
- 文字送信とオーブ音声会話が同じ経路を使用する。入力欄マイクは文字起こしのみ。オーブは約3秒無音で送信し、読み上げ後に待ち受ける。実会話は3往復で停止し、再タップが必要。権限・認証・通信・読み上げエラー、画面非表示でも停止する。再試行はしない。
- モデル claude-sonnet-4-6、出力上限512 tokens。現在の入力は2048 UTF-8バイトまで。APIに渡す履歴は直近3往復まで、システム文込み4096 UTF-8バイト以内になるよう古い往復を除外する。今回の質問を黙って切り詰めない。
- 8192入力tokensの保守的予約、設定単価 input 3 / output 15 USD per MTok。1回の推定最大費用は **0.032256 USD**。実費は返された使用tokensで算出する推定値であり請求確定値ではない。
- 予約と利用額は既存 ai_operations に追記する。FINANCEのプリペイド台帳で確認でき、各回答にも費用・tokens・操作IDを表示する。月額1 USDの旧設定はこの経路では参照しない。
- 同一送信IDは再使用不可。同時実行不可、開始間隔5秒以上、承認ごと最大1〜10回、既存の全AI合計UTC日10回制限も維持。費用不明の通常会話が残れば後続も停止し、予約を保持する。既存completed/uncertain記録は変更しない。
- 会話の永続保存は既存の「会話を保存」設定に従う。設定ONの成功した実会話は既存記憶APIに保存し、再読み込み後は認証して「記憶を再読込」で最新3往復を表示・文脈へ復元する。OFFならそのページ内だけ。端末へ新たに会話本文や鍵を保存しない。記憶機能の既存保持期限・件数制限を引き継ぐ。保存失敗は画面に表示する（回答は保持）。

## 別途承認後の初回テスト手順

この配備だけでは実APIは有効にならない。キー変更や停止解除、実送信は今回行わない。

1. ユーザーから「Preview通常会話を1回実送信する」明示承認を受ける。
2. Anthropic実残高、自動チャージOFF、共有キーの他経路消費を確認する。過去申告の約3.04 USDを現在残高と扱わない。既存台帳のcompleted・未確定予約と照合し、確認済みの残高に既に含まれる確定費用は二重控除しない。他アプリの利用が不明なら有効化しない。
3. 承認された操作として **Previewだけ** に既存プリペイド設定を適用する。現在は未設定のまま。`JARVIS_PREPAID_SNAPSHOT` は verified=true、autoRechargeOff=true、確認時点 observedAt(ms)、確定費用が残高に反映済みの境界 settledThrough(ms)、balanceMicroUSD（整数）を持つ。未確定額は境界以前でも控除対象。全て確認値を使い、作り値を設定しない。
4. `JARVIS_PREPAID_APPROVAL` は purpose=`conversation`、id=`chat-`で始まる新しい8〜64文字の識別子、previewDB=`5ec09d38-2ed8-4c7a-ba67-bfd9c2ed32d0`、model=`claude-sonnet-4-6`、snapshotObservedAt、maxCalls=1、expiresAt（残高確認後15分以内）。同じidの使い回しで回数は復活しない。旧one-shot/Threads承認では通常会話を許可しない。
5. 既存キーを保持し、モデル・料金設定を照合後、`JARVIS_PREPAID_LIVE_ENABLED=true` をPreviewだけに適用する。初回maxCalls=1を厳守する。
6. 認証後、音声設定の「通常会話の承認状態を確認」→「Claude通常会話」を選択する。短い文字入力かオーブから1発話だけ送る。初回の全体上限予約は0.032256 USD。正常終了・費用記録・読み上げを確認する。模擬応答のブラウザテスト結果を実Claudeの回答と扱わない。
7. テスト後はPreviewの実送信フラグをfalseに戻し、承認を失効させる。結果不明・エラーなら同じ送信を繰り返さず、操作IDで調査する。未確定予約を消したり、完了扱いに書き換えたりしない。期限切れ・回数到達でもサーバーは拒否する。

## 未検証と復旧

- 実API送信は未実施。実残高/共有キーの最新状況は取得していない。Anthropic側全体残高の自動取得・保証機能ではない。
- PC/スマホ幅の模擬ASR/TTSテストはiPhone実機の代替ではない。Safariでマイク・読み上げ・再待ち受けが拒否されたら、表示に従いオーブ再タップする。起動時「ジャービスです」の端末内挨拶は維持する。
- Productionへの適用は別途承認・Production専用の設計審査が必要。この経路はProductionで拒否する。
- 障害時は実送信を停止し、モックを選ぶ。DBスキーマ追加やデータ削除は不要。Previewコードを戻す場合も未確定予約を残し、実送信設定を停止した状態で行う。一般APIの安全停止は解除しない。
