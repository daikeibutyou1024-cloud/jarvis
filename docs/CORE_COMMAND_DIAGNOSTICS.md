# Preview：BTC音声/文字コマンドの正規化と診断

原因は、従来の少数の完全一致表現が「今日のビットコインの報告をして」を含まず、呼びかけ除去も日本語の一部表記に限定していたこと。音声認識そのものやClaude停止を原因と断定しない。

lib/core-command.jsのnormalizeCoreCommand/isBTCReportCommandを使用する。音声の確定文と文字入力は同じfreeDialogue経路へ入り、NFKC、ゼロ幅文字、呼びかけ（ジャービス/ジャーヴィス/J.A.R.V.I.S./JARVIS等）、語間の空白、終端記号を整えてから判定する。表示用・会話履歴の原文は変更しない。

対応例：
- ジャービス、今日のビットコインの報告をして
- J.A.R.V.I.S.、今日のビットコインの報告をしてください
- BTCの状況を教えて
- 今日の相場は？
- 今日の報告をください

対象はBTCの報告・レポート・状況・価格・相場・ニュース等と既存の買い時/上がりそうという照会。別通貨、為替、売買/送金指示、教育的質問、複合指示を単なるBTC取得へ広げない。自由な言い換えすべてを理解するAIではない。

BTC報告後の「それはなぜ？」「ニュースを詳しく」は取得済み文脈を参照する。呼びかけ正規化を追加質問にも共用し、再取得や有料AIへの自動切り替えは行わない。

## 診断パネル

COREの「音声・文字コマンド診断」に、最後に処理した確定文、正規化した文、音声/文字の区別、判定intent、処理状態、固定の失敗理由、許可した取得元/段階/コード/HTTP状態を表示する。

診断自体は最新1件をJavaScriptメモリとDOMだけで保持し、サーバー・会話履歴・IndexedDB・localStorage・コンソールへ保存しない。認識途中の文は診断へ記録しない。会話本文の既存履歴保存とは別で、通常の安全な会話原文は従来どおり保持する。

パスワード・APIキー・トークンらしい表現、既知の認証情報、メール等は診断の原文/正規化文とも非表示にし、無料会話の処理・履歴追加も止める。全角やゼロ幅を含む認証情報の表記も検査する。失敗時に任意の例外message/stack、URLクエリ、ヘッダー、応答本文を診断へコピーしない。ログアウトで診断を消す。

## 失敗の扱い

BTC判定済みで価格・日足・ニュースが不足する場合はbtc_reportのままacquisition_failed/partial_acquisitionを表示する。レポートAPI自体が503等で失敗した場合も「BTCコマンドは認識したが取得に失敗」と案内し、対応外の質問にしない。公開データのHTTP/NETWORK/TIMEOUT/FORMAT等だけを安全なメタデータとして扱う。データを推測で補完しない。自動再試行や有料AIは使わない。

既存の無料連続会話・音声設定・端末内履歴・公開データの取得先/キャッシュ・Productionの停止条件を維持する。Production/main/実DB/バックアップ/環境変数は変更しない。
