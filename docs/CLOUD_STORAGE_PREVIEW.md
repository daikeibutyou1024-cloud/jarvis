## 保存・認証・互換性

- `/api/autonomous` は既存8時間HttpOnlyセッションをサーバー側で検証する。パスワードヘッダーだけでこのAPIを使うことはできない。対象ブランチ、HTTPSの許可Previewホスト、実行時 `CF_PAGES_URL`、停止フラグ、DB内の専用識別行を検証する。Production・他Previewブランチは拒否する。
- 既存認証は単一管理者であり、複数アカウント認証ではない。ownerはサーバー側の管理資格情報から一方向ハッシュで導出する。クライアントにownerを指定させず、すべてのSQLをownerと案件IDで限定する。同じ管理者の別セッション/許可Preview URLからは復元できる。異なる管理資格情報のスコープとは混在しない。
- 管理パスワードを変更するとownerスコープも変わる。変更時の再紐付けは別途承認・検証が必要。今回パスワードを変更しない。
- 新規案件は有効化後のサーバージョブで作成する。収集は既存の固定公開RSS、生成は既存モック。ブラウザのlocalStorageを実行エンジンに渡さない。画面を閉じても既に確定した版と状態はクラウドから復元できる。ただし今回は定期起動・切断後のジョブ完遂を保証するバックグラウンド基盤を起動しない。中断はリース期限後に手動再試行する。
- 旧端末キーには書き込まず、旧案件は従来どおり閲覧・端末編集できる。旧案件を保存してもクラウド移行しない。クラウドは別のメモリビューとして読み込み、一覧に保存先を明示する。ANALYTICSは取得済みクラウド原稿を参照集計し、端末成果・収支はそのまま維持する。未移行の端末収支をクラウド取得済みと表示しない。
- 新規クラウド原稿は編集停止から約900ms後に自動保存する。承認・差戻し・修正は既存操作に連動して保存する。編集中の変更は承認を解除する。承認はサーバー側で現在の版・業務完了・出典/内容の本人確認を要求する。承認しても公開しない。
- 保存エラー時は成功と表示しない。フォームと旧端末データを保持し、自動再送しない。読み取りで状態を確認後、同じ操作IDの再送で確定結果を復元できる。編集内容が変わっている場合は不明な保存を上書きしない。画面案内に従いコピー退避・再取得を行う。
- 確定前の入力はクラウド保存済みとは扱わない。未保存中に閉じる場合はブラウザの離脱警告を利用するが、iPhoneのアプリ強制終了等で未保存文字を完全保護できるとは保証しない。
- 履歴画面は過去版・操作・原稿ハッシュを認証付きで参照できる。過去版の参照は現在の編集や承認を置き換えない。

## 排他・原子性・上限

- 管理者スコープごとに1つのリース、期限60秒、取得ごとに単調増加するfence、ランダムlease_ownerを使用する。無期限のロック・定期延長・常時プロセスはない。
- 書き込みごとにlease_owner/fence/期限を検証する。期限切れ/新しいワーカーに交代した古い処理は保存できない。クライアントの時計やowner/fenceを信用しない。
- 原稿保存はD1 batchのトランザクションにより、現行版の比較更新・原稿追記・出典初期保存・履歴を原子的に処理する。競合は409。ジョブ・日次報告は後続チェックポイントで、失敗時は確定した原稿を消さず、状態再取得と再試行で整合させる。
- mutation_idとrequest_hashで同じ保存操作を冪等化する。同じ操作IDで異なる本文なら409。出典URL＋公開日時の一意制約でテーマの二重作成を防ぐ。未公開原稿の版は追記のみで、過去版を上書きしない。
- 1日100回までの保存/ジョブ操作、管理者あたり100案件、1案件100版、全スコープ合計1000原稿版・1000ジョブ、本文240KB・リクエスト256KBを上限とする。上限到達時は停止し、自動削除・上限の自動緩和をしない。これはアプリ上の防御でありCloudflare請求の上限保証ではない。
- API入力は操作/キー/サイズ/案件ID/版数を制限し、原稿に秘密値や一般的なAPIキー形式を検出したら保存拒否する。DB障害の内部エラーや資格情報をレスポンスに含めない。AI出力をSQLやツール指示として実行しない。
