# CORE共通の日本語音声出力

Previewだけの変更。Claude等の実API送信や承認設定・環境変数・DBの変更は行わない。

## 共通処理

通常会話、承認済みClaude応答の表示経路、BTC公開レポート、既存のローカル応答は同じspeechSynthesis出力を使う。言語はja-JP、利用可能な日本語音声を明示選択する。getVoicesとvoiceschangedの両方で一覧を更新する。日本語音声が列挙されなければlang指定によるOS選択を利用し、失敗は隠さない。

初回のCOREタップで、音声未初期化なら「音声会話を開始します」という通常の短い音声を、認証などのawaitより前に直接呼ぶ。終了後にマイクを開始する。失敗した場合も文章での利用は継続でき、回答の「音声で再生」を提示する。無音音声、AudioContextの隠れた再生、setIntervalによるresume連打等はしない。Safariの自動再生許可を恒久的に解除できる保証はない。

認識コントローラーの実際のactive状態（開始待ち・停止待ちを含む）を参照し、認識中にTTSを開始しない。自動回答は認識終了後。認識中に既存回答を明示再生しようとした場合は、まず認識を止め、再タップを案内する。手動再生はAPIを呼ばない。

## 長文と中断

長文は句点などを優先して最大140 Unicodeコードポイントずつ分割し、各音声のendイベントから次を順に再生する。全体の参照を保持し、COREのspeaking状態を一つの出力として管理する。短い音声単位ごとの開始・終了タイムアウトを持つ。途中エラーやイベント欠落では勝手に再送せず、未完了の部分を「音声で再生」から再生可能にする。開始イベントなしの終了を再生成功と扱わない。

停止・音声OFF・ログアウト・画面非表示で残りの再生と自動待ち受けを中止する。遅れたstart/endイベントで復活させない。画面非表示中に手動チャットの応答が遅れて届いても自動再生しない。

## 設定と操作

CORE直下に音声ON/OFFと音声状態を表示する。既存 `jarvis.speech.preference.v1` だけに希望設定を保存し、会話本文や鍵は保存しない。設定なしはON。明示保存されたOFFを勝手にONへ変更しない。ON/OFFは通常会話とBTCを含むCORE自動音声に共通適用する。OFFでも本人の「音声で再生」操作は可能。

読み上げに失敗したら同じ回答を保持してボタンを表示する。手動再生が拒否されたら、その状態も表示する。音声をオフにすると会話を停止する。次にCOREを押せば文字表示中心の利用はできる。自動待ち受けは従来の回数・承認・3往復制限を維持。

## 検証の限界

単体テストとPC/スマホ幅のChromiumで、Safariに似せた初回操作制約・音声一覧遅延・長文・認識排他・再生拒否・通常会話/BTC・手動再生でのAPI再送禁止・OFF保存を検証する。実Claudeを呼ばず、実マイクも使用しない。

iPhone Safari実機の音声出力は未確認。端末のメディア音量、出力先、利用できる日本語音声、OS側の制約に依存する。初期化成功やstartイベントだけで、端末から実際に聞こえたと断定しない。
