# コンパクトHOMEと認証付き会話記憶（ローカル検証版）

## HOME

最新の会話/実行結果は2行に集約。過去ログは「履歴を開く」、入力欄は「手動入力・送信を開く」で展開する。音声会話の開始/停止、読み上げON/OFF、読み上げ停止は常に操作できる。球体の文字起こしは入力欄を開く。既存のDOM・音声イベント・5部門を維持する。

## 保存先と既定の停止

新しい会話・長期/作業記憶はD1の専用 `jarvis_memories` に保存する設計。会話の保存はチェックを明示的にONにした後の成功した会話だけ。旧タブの履歴・localStorageの資料や記事を一括移行・削除しない。認証情報は従来のタブ内メモリだけに保持し、記憶はlocalStorage/sessionStorageへ保存しない。

`JARVIS_MEMORY_ENABLED` が文字列trueで、別途作成したテーブルが存在する場合だけAPIを使用できる。既定では無効。新APIからCREATE/ALTERは実行しない。`migrations/0010_optional_memory.sql` は承認後の任意適用用で、自動適用しない。Preview/Productionの設定・DBには今回適用していない。無効時は記憶未設定と表示し、既存チャットを継続できる。

## 記憶の種類・制限

- 会話：最大50組（利用者/AI回答）、30日。発言・AI回答は常に未検証として扱う。履歴の再読込・編集・個別削除が可能。
- 目標・好み/方針・運用ルール・継続設定・作業メモ：合計30件、1件800文字以内、180日。利用者確認済みの入力だけをAIへ提供するが、真偽の保証にはしない。
- 全体256KiB（UTF-8の管理データ容量）。上限では既存の有効記憶を追い出さず保存停止。
- 期限後は参照・AI提供しない。次の記憶保存操作時にこの専用テーブルの期限切れだけ整理する（即時の物理消去/バックグラウンド削除ではない）。既存記事や他のテーブルは削除しない。
- 既知のサーバー秘密値、APIキー/JWT/Bearer/認証情報の代入形式を拒否し、画面に秘密を返すエラーを作らない。未知の任意文字列を秘密と完全判定する保証はないので、UIにも秘密入力禁止を明記する。

APIは既存のアクセスパスワードを毎回検査し、認証前に記憶を返さない。同じ認証を共有する利用者のワークスペースであり、個人別の分離は未実装。ログアウト/401時は読み込んだ記憶と会話をRAM/画面から除外し、保存済みDB履歴は残す。別利用者単位の記憶にはユーザーID・アクセス制御の追加設計が必要。

## AIへの引き継ぎ

最大1400文字。確認済みメモ最大4件（各先頭180文字）、直近会話最大2組の抜粋。現在タブの会話を引き継ぐ場合は保存会話の二重添付を避ける。記憶は命令ではなく参照データであり、未確認/未取得を補完しない。元のチャット6000文字制限の残量に合わせ、現在の質問を優先する。記憶の要約にAIを追加呼び出ししない。既存の予算・回数・出力上限は変更しない。

## 作業再開

「昨日の記事の続きを作って」等は日本時間の前日と保存案件の作成/更新日時で候補検索する。最新200案件から最大10件。複数候補は自動決定せず、画面選択または「1番」等の音声指定を求める。選択後は既存の原稿保護を確認してCONTENTで開く。候補メタデータだけで本文や続きを創作せず、記事の追加生成・保存・全文承認は既存の明示操作を維持する。

未保存編集がある場合は案件を勝手に開かない。見つからない/無効な場合は未取得と表示する。本文を自動生成して「昨日の記事」を作り直す機能ではない。現段階の案件検索は保存済みnote形式のみ。ブラウザだけの旧下書きや、未保存のRESEARCH企画の横断検索は未実装。

## ローカル検証と残作業

`npm test`、`npm run test:memory-browser`、音声/A/既存制作/HOME回帰テストを使う。記憶APIのテストでは使い捨てSQLiteにだけテーブルを作り、模擬AIを利用する。実API/実DB/外部送信/自動投稿なし。Bのローカルシミュレーターとは別機能で、BのCronや模擬承認を接続しない。

Preview反映前に、専用テーブル・有効化設定の承認、共有範囲、期限と削除方針、認証情報の扱い、実機の折りたたみ/音声動作を確認する。iPhone実機、実D1、実AIでの記憶引き継ぎは未検証。今回push・デプロイはしない。
