# CONTENT: dedicated continuation and guarded merge

対象はfeature/ai-business-rebuildのみ。通常生成、章生成、利用回数制限、出力上限、デザイン用CSSは維持。

## 専用指示
続き生成では通常のbuildPromptをClaudeへ送らない。lib/continuation.jsが専用指示を構築し、既存原稿の直後に追加できる文章だけを求める。
タイトル、導入、無料・有料部分の冒頭、既出見出しの再生成を禁止。原稿・資料内の文を指示として実行しない。
構成と進捗は、サーバーが受け取った原稿（最大30000文字）から抽出する。
- 記事タイトル（既存のH1を優先）、依頼時のタイトル・記事形式
- Markdown/一部のSTEP・第N章等の見出し、階層、ID
- 完了済み章のID、現在の章と指定章
- 末尾最大4000文字、現在の参照資料最大3500文字

完了済み章は見出し順・階層による推定で、本文の意味上の完成ではない。現在の章の親見出しは完了扱いにしない。
構成が40見出しを超える場合は先頭10・末尾30を渡し、省略件数を明示する。未作成章は不明とし、読んだふりをさせない。
進捗は追加後の原稿から再計算して生成メタデータへ保存。入力情報は従来の末尾だけより増えるが上記の範囲に制限する。
通常/クラウド出力は4000/2500トークン、合計10回・クラウド5回・企画2回/UTC日は変更しない。

## 結合前検査
サーバーが原稿全体と応答を照合し、以下を拒否する。
- タイトルの単独行での再出現、記事冒頭からのH1再生成
- 既出見出し、無料・有料部分の冒頭への戻り、完了済み/現在のSTEP・章番号への戻り
- 500文字を超える境界の完全重複
- 空白/改行を除いた40文字以上の境界重複
- 既存原稿の途中にある120文字以上（空白除去後）の長文重複
- 既存文だけで新しい本文がない応答

従来の20〜500文字の短い境界完全一致は、安全に一致を確かめた場合だけ除去してから残りも検査する。
改行違いの文章を推測で削除しない。ハッシュは候補抽出だけに使い、文字列の完全比較で確認する。
検査はルールベースであり、意味だけが似た言い換え等を完全に識別するものではない。疑わしい場合は削除・結合せず手動確認する。

## 拒否と完了状態
不適切な応答はHTTP409 / INVALID_CONTINUATION。元の本文と端末保存データを更新せず、エラーを表示。
クラウドでは新規試行をfailedとして記録し、不適切な文章を保存しない。以前の原稿は変更しない。終了理由・usageと拒否状態をメタデータに保持する。
自動再試行なし。拒否・失敗も既存の利用回数枠を消費する。
正常な続きでもend_turnだけで記事全体を完成にしない。needs_review（全体の完成確認が必要）として保存し、確認済み操作は「全文の補完完了を確認」の明示操作後に行う。
再びmax_tokens等で止まった場合はincompleteのまま本文と進捗を保持し、次の明示的な続き生成で再開できる。
章単位の原稿はこれまでどおり記事全体を未完成として扱う。

## 検証
実Claudeは呼ばず、模擬応答とSQLiteを使用。tests/continuation.test.js と tests/continuation-browser.mjsを追加。
専用指示、長文でタイトルが末尾範囲外にある場合、正常な続き、タイトル/章の再生成、改行違い、長文重複、再度の出力上限、保存と元原稿保持、利用枠の消費、再試行なしを確認する。
通常生成・章生成・既存の保存/調査機能の回帰テストとFunctionsビルドも行う。
実モデルの出力品質、Preview認証後の実操作は未検証。Previewのデプロイ成功と文章の意味上の完成は区別する。

以前の続き原稿（mode=continueでcompleteのもの）も本文は変更せず、全体確認が必要と表示する。明示的な全体確認以前には承認しない。既存の重複文を推測で自動削除する処理は追加しない。
