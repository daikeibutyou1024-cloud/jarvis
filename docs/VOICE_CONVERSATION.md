# 明示開始の音声会話

## 使い方

HOMEの「音声会話を開始」を押し、初回に認証とブラウザの音声認識/マイク許可を行う。発話が確定すると送信ボタンを押さず送信し、AI回答を読み上げる。読み上げ終了後に音声認識を再開する。

- 球体/◎は従来の文字起こしを維持。自動会話中に押すと会話を停止する。
- 「音声会話を停止」でマイク・読み上げ・次の自動送信を停止する。
- 読み上げ停止、ログアウト、別部門への移動、画面非表示でも自動会話を停止。画面へ戻っても勝手に再開しない。
- 手動入力は従来どおり使用可能。入力中のテキストを新しい音声で無断上書きしない。手動送信で自動会話から切り替える。
- 停止時点ですでに送信済みのAI要求は取り消し/無課金を保証しない。応答は画面へ表示する場合があるが、自動読み上げ・マイク再開はしない。

## 発話終了の判定と二重送信対策

`SpeechRecognition`/`webkitSpeechRecognition`を利用し、途中結果を表示する。ブラウザのspeechendと認識結果の変化に約1.2秒の待機を組み合わせて認識を終了する。認識サービスが先に終了した場合も待機後に確定結果だけを送る。生の音量や実際の無音時間を計測しているわけではない。独自の追加マイクストリーム・音量解析用の追加許可は要求しない。

確定前の文字、空文字、2000文字を超える発話は送信しない。同一認識ターンは一度だけ送信し、古いセッションのイベントは破棄する。AI応答待ち・TTS中は認識を再開しない。送信・利用回数・予算管理・出力上限は既存のチャットAPIをそのまま使い、自動再試行しない。

認識が5秒で開始しない場合や30秒間発話を検出しない場合も停止する。認識エラー、API失敗/予算停止、認証失敗、読み上げの失敗は再開操作待ちとなる。認識停止後にendイベントが来ない場合もタイムアウトして再開可能にする。TTSが5秒以内に始まらない/180秒以内に終了しない場合は自動会話を止め、表示された回答と再開操作へ戻す。

## 認証

従来どおり同じタブのJavaScriptメモリだけに保持する。音声会話開始時に確認するため、初回発話の後に認証で遮られる操作を減らす。同じタブ内の次の発話では再利用する。localStorage/sessionStorage/URL/cookieへ新たに保存しない。401で破棄し、再認証は明示操作から行う。再読み込み/新規タブでは認証が必要。

## iPhone Safariの制約

- WebKitはSiriと同じ音声認識エンジンを利用する旨を案内している。端末のSiri設定・音声認識/マイク許可・対応状況に依存する。
- ページを開くだけでマイクを有効にしない。開始/認識再開/読み上げに利用者の操作が必要になる場合があるため、明示開始と停止・再開ボタンを残す。
- 認証ダイアログを挟んだ後や回答受信後の認識再開が拒否された場合も、再開ボタンへ戻す。ユーザー操作制約を回避する仕組みは追加しない。
- 無音の検出精度、長い発話の区切り、読み上げ開始・再開、Bluetooth、画面ロック、着信による中断は実機未検証。ブラウザの認識サービスの通信/オフライン動作も保証しない。

## 検証

`npm test` と `npm run test:voice-browser`。音声・マイク・AIは全て模擬で、ブラウザはlocalhost以外を遮断。自動送信・二重イベント・AI/TTS中の遮断・認証再利用/401・停止・手動入力・認証情報の非永続化を確認。実API・実DBは利用しない。
