# VIRTUAL OFFICE — Preview運用と安全確認

対象：`feature/ai-business-rebuild` の `/office.html` のみ。
Production・main・jarvis-calendar・バックアップ・既存の環境変数/APIキーは変更しない。

## 今回利用できる機能

- 12職種のオフィス、担当割当、企画/台本/記事/投稿下書き/制作指示書/分析の依頼。
- オーナーによる下書き編集、版の保持、内容承認/修正依頼/却下、作業・承認履歴。
- 投稿/契約/支出の承認キュー。承認は記録のみで、外部の実行処理は存在しない。
- 根拠を添えたJPY収益/経費の手入力。USDのAI費用・未確定予約と分離する。
- 初期OFFの端末内保存。専用IndexedDB `jarvis-virtual-office-v1` を使用し、既存ストアを開かず移行・削除しない。OFFに戻してもデータを保持する。
- 複数タブでの更新競合はrevision照合で拒否し、再読込を案内する。JSON書出しが可能。

12人は担当役割であり、12個のモデルが常駐する構成ではない。社員は自律起動せず、オーナーが明示的に依頼・実行する。
手動の成果物には「オーナー手入力」を表示する。未実施の調査、投稿、売上や実AI生成を捏造しない。

## 実AI実行経路：実装済み／本環境では停止

`/api/office` → `runOfficeDraft` → 既存Anthropicクライアント。
既存のCORE無料会話や汎用 `runAI` の停止措置は変更しない。
12職種ごとの指示とオーナーの参考資料を入力し、下書きだけを生成する。
検索、動画/画像の生成、プラットフォーム接続は行わない。調査担当も提供資料の整理までで、外部調査の実施を主張しない。

実行にはすべてが必要：

1. 現在のPages Preview設定を読めることとDB分離の再確認。
2. Preview D1に新規専用スキーマを明示適用し、既存のAI台帳・認証を保持すること。
3. `JARVIS_VIRTUAL_OFFICE_ENABLED=true`（既定はOFF）。
4. `JARVIS_OFFICE_LIVE_ENABLED=true`（既定はOFF）。
5. 最新の照合済みプリペイド残高スナップショット。自動チャージOFF・他経路利用の反映。15分を超えた確認値は拒否する。
6. 社員別月額費用上限（UTC月、初期0、0〜1 USDの明示設定）。既存の共通回数制限：UTC日10回も維持する。
7. タスク画面で「1回0.032256 USDの費用承認を記録」。タスクID/版/担当/実行IDを確定する。
8. 管理者の別途承認 `JARVIS_OFFICE_APPROVAL`。通常会話の承認とは互換性がない。
9. その後に本人が「実Claudeで1回制作する」を押す。承認設定だけで送信しない。

モデル `claude-sonnet-4-6`、入力資料とシステム文のUTF-8合計4096バイト以内、最大出力512。
保守的な1回予約額0.032256 USD（入力上限8192トークン×3 + 出力512×15、単位microUSD）。
実費表示は応答トークン×設定単価の推定で請求書確認済みではない。
入力・成果物の認証情報パターン、実キー値を保存/モデル入力から拒否する。
参考資料は未確認データで、資料内の命令を実行しないようシステム指示に明記する。

期限付き承認の形式（値は対象タスク画面と最新の残高照合から取得、今回設定しない）：

```json
{
  "id": "office-<unique-id>",
  "purpose": "office-draft",
  "previewDB": "5ec09d38-2ed8-4c7a-ba67-bfd9c2ed32d0",
  "taskId": "<task-id>",
  "taskVersion": 2,
  "agentId": "seo",
  "runId": "<run-id>",
  "model": "claude-sonnet-4-6",
  "maxOutput": 512,
  "maxCalls": 1,
  "maxMicroUSD": 32256,
  "snapshotObservedAt": 0,
  "expiresAt": 0
}
```

`expiresAt` は確認済み残高の `observedAt + 15分` 以下。0や例示IDでは利用できない。
APIキーをこのJSONに記載しない。既存のキー・料金・スナップショット設定をサーバーだけで使用する。

## 現環境の停止理由

Cloudflare Pages構成の読み取りAPIがHTTP 401を返したため、現在のD1バインディングを確認できていない。
提供済みのDB IDを知っていても、現在の接続を検証したことにはならない。
このため、リモートSQL・フラグ・承認設定を実行しない。クラウド保存・実AI制作は稼働済みと扱わない。
端末内管理を先に利用できるようにし、クラウドとの自動移行は行わない。
実API送信は0件。課金テストは別途の費用承認・有効化確認後に本人が行う。

## Preview専用DB準備（未実行）

`release/virtual-office-preview.sql` は追加専用でローカルSQLiteに対して検証した。
ドメイン5表 `vo_agents / vo_tasks / vo_approvals / vo_runs / vo_metrics` と、
全体revision・復旧スナップショット用 `vo_workspace` の計6表、4索引、初期社員12行とworkspace1行。
既存の汎用agents/tasks等や既存business/cloudテーブルを改変しない。
`IF NOT EXISTS` で非互換な既存表を黙認せず、同名衝突があれば停止する。
SQLの適用前後の行数・メタデータを比較し、既存データ本文を取得しない。

適用前の必須確認：現在のPreviewバインディングが `5ec09d38-2ed8-4c7a-ba67-bfd9c2ed32d0`、
Productionが別DBであること、Freeプラン/残容量、`vo_*`名の不在、物理識別行と既存AI台帳/ai_usageの存在。
結果不明ならSQLを再実行しない。現在は401が解消するまでこの段階へ進まない。

クラウド更新はworkspaceのCASと変更したドメイン行だけを同じD1 batch内で更新する。
古い版・並行操作は拒否し、二重課金予約もai_operationsの一意IDと原子的な残高/社員上限判定で拒否する。
workspaceの保存上限1 MB、端末内は500タスク。上限・容量不足では追加を停止し履歴を削除しない。

## 障害・復旧

- 送信前に実行予約と費用承認を永続化する。並行実行と5秒以内の連続有料リクエストを停止。
- 送信後の通信失敗、使用量不明、サーバー停止、保存結果不明は自動再試行しない。
- 未確定予約は月をまたいでも保持。オフィスのrunning/uncertain、既存Anthropic台帳の未確定があれば新規制作を停止する。
- 結果不明時はtask/run/operation IDで管理者がAnthropic利用記録と照合するまで再実行・予約解除しない。
- 成果物はレビュー待ち。出力上限で打切り/終了理由不明なら本人が完成させるまで承認不可。
- 外部操作の承認は制作物の版に結び付く。編集後は再承認が必要。
- UIをOFFにすれば端末内保存を保持したまま従来COREへ戻れる。既存データを消す復旧はしない。
- 必要なら、別途権限を確認した上でPreviewのオフィスフラグをOFFにする。今回は設定を変更しない。
- コードを戻す場合もPreviewだけに限定し、現行COREを維持できる検証済み版へ戻す。Production/main/DB/バックアップを操作しない。
