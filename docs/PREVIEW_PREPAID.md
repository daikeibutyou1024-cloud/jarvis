# Previewのプリペイド残高管理

Preview専用。月額1 USDのアプリ内判定をこの経路から撤廃する。`AI_MONTHLY_BUDGET_USD` と月次開始額はプリペイド経路で参照しない。過去互換・Production保護のため旧設定値と一般の停止済み生成処理は変更しない。通常の実AI停止は維持し、旧1回テスト許可だけでも新方式を有効化できない。

FINANCEの「API残高・使用履歴を取得」で確認する。Threads下書きは同じ画面の折り畳み内に配置する。

## 残高と履歴

本人報告の残高約3.04 USDは「報告値」として表示する。現在のAnthropic実残高を取得した値ではない。基準日時と、どの確定費用までその残高に反映済みかが未照合の場合、報告値から未確定予約だけを控除した参考推定を「未照合」と表示し、実APIを解放しない。この参考値は他アプリの追加消費や基準後の未取得費用を反映せず、送信許可の残高として使わない。月間1.19 USDを残高からもう一度差し引く方式にはしない。

確認済みスナップショットは残高microUSD、確認日時、請求への反映確認が済んだ締切時刻、確認済み・自動チャージOFFをサーバー側に記録する。推定残高は基準残高から、締切後の費用と未確定予約を差し引く。未確定は `MAX(charged_micro,reserved_micro)` を保持し、月を跨いでもリセットしない。基準残高に既に反映された過去の確定費用は二重に控除しない。OpenAIなど別providerの費用はClaudeの残高計算に混ぜず、履歴そのものは表示・保持する。

既存ai_operations/ai_usage、completed/uncertain、usage_json、照合履歴は削除・初期化しない。新しい生成は既存台帳へ事前予約し、使用トークンと設定単価に基づく推定費用を記録する。新規行のusage_jsonに残高基準・計算時刻・推定残高も記録する。GET表示では旧行の状態変更や掃除処理を実行しない。

この推定は請求書や共有アカウントの実残高を保証しない。他アプリによる消費・集計遅延は自動取得できない。自動チャージ設定も変更しない。Anthropicが残高不足を返した場合は固定の不足表示で停止し、再試行しない。

## Threads文生成

手動ボタンで作成する下書きのみ。Threads接続・実投稿・Cron・自動実行はない。日付は日本時間（JST）。固定operation ID `jarvis-preview-threads-YYYY-MM-DD` により、並行タブ・ページ再読み込みでも処理開始日の生成は1回。エラーや結果不明もその日の枠を消費し、自動再試行・追記生成をしない。画面も試行後は停止する。

モデルはclaude-sonnet-4-6、最大出力256トークン。テーマ256文字、最終prompt2048 UTF-8 bytes以内。入力4096トークン相当の余裕と設定単価3/15 USD per millionから、事前予約は最大0.016128 USD。出力上限による途中終了も追加要求せず、手動編集を案内する。一般の日次回数制限も維持し、履歴削除による回数返還は行わない。

## 停止状態と将来の実API承認

現在の実API・Threads実投稿は未承認のため停止のまま。環境変数・キー・Anthropicの課金設定・Productionは変更しない。既存のモック音声会話は利用できる。

将来の実API実行には別途明示承認が必要。`JARVIS_PREPAID_LIVE_ENABLED`、確認済みの `JARVIS_PREPAID_SNAPSHOT`、目的と有効期限を限定した `JARVIS_PREPAID_APPROVAL` をPreviewだけに設定する。Threads承認はJST日付と1回制限を含む。残高基準から15分以内、正しいPreview DB識別行・モデル・料金・署名付き認証が必要。クライアントの入力や旧月次許可では解除できない。スナップショットがない、古い、残高不足なら送信前に停止する。

1回の音声テストも、月額方式からこのプリペイド方式へ切り替えるが、既存の固定1回IDと128出力トークン制限は維持する。常時の実AI会話を有効にする変更ではない。

## 検証

合成キー・模擬provider・使い捨てSQLiteで、月額0 USDでもプリペイド条件を満たせば処理可能なこと、旧許可では解除できないこと、旧記録不変、二重控除防止、予約保持、並列処理、日付境界、1日1回、出力制限、残高不足停止、実投稿なしを検証する。実API・本番DBへはテスト送信しない。
