# note記事の制作・全文確認フロー

対象: feature/ai-business-rebuild。前回の保存・予算管理を維持し、優先順位2「記事制作を一巡」と、優先順位3のうち「版にひも付く全文確認・確認待ち一覧」を追加する。

## 利用手順

1. RESEARCHで資料を取得・確認し、企画または選択した確認済み資料をCONTENTへ引き継ぐ。
2. CONTENTの「現在のRESEARCH資料・企画を取り込む」を押す。テーマ・対象読者・形式・条件、採用する企画メモ、構成を確認する。外部事実を使わない考察記事に限り、その方針をチェックできる。出典がある記事の確認を省くための機能ではない。
3. 「制作案件を保存」。資料スナップショット・企画メモ・構成・制作条件・本文を同じ案件と版で保存する。本文が空でも企画段階として保存可能。保存ではAIを呼ばない。
4. 不足章の一覧から章を選び、既存の生成ボタンを使う。生成は明示した操作ごとに1回。自動連続生成・自動再試行はしない。無料記事の既存章を補完するときは「続きを作成」を使う。有料記事の不足成果物は既存の章追加・補完にも対応。
5. 長文は先に制作案件を保存し、クラウドの章・続き生成で再開する。保存版の本文をサーバーで読み込み、指定章の末尾と限定した構成・資料だけをAIへ渡す。サーバーでは原稿全体を保持し、後続章を残して結合する。AIが全文を読んだと扱わない。本文の上限は60000文字（管理用出典などを含む応答は70000文字以内）。従来の通常APIへ本文を直接渡す場合の30000文字制限は変更しない。
6. 生成終了と記事全体の完成は別。章だけの生成・出力上限停止・不明な終了状態を自動で全文完成にしない。必要な補完後、全文の手動補完完了を確認して制作案件を保存する。不足一覧にタイトル・章・根拠・有料成果物などが残れば全文確認を通せない。
7. 保存版の全文について、事実と出典・実用性・権利・個人情報・PRや実績表現の5項目を人が確認し、「この保存版の全文確認を記録」。機械検査では意味上の正確性・販売価値を保証しない。
8. 「確認済みの原稿を出力」でMarkdownをダウンロードする。全体・無料部分・有料部分を画面でも確認できる。管理用の状態・重複した資料付録をそのまま販売原稿へ混ぜず、参考資料を別に構成する。noteへの投稿、販売、価格設定は行わない。

途中からは「制作状況を取得」またはクラウドの版一覧で案件を開く。確認待ち／補完中／確認済みを表示。案件一覧は50件ずつ、次のページを取得できる。

## 保存と確認の保護

- 制作メタデータは既存の `document_revisions.payload.workflow` と、同じpayload内のtopic/audience/notes/format/evidence/outputに保存する。既存の版・原稿を一括変換しない。
- 追加テーブルは `editorial_reviews` のみ。案件ID・版・本文と制作条件のSHA-256・5項目の確認・日時を保存する。`0006_editorial_reviews.sql` は任意の手動適用用。認証付き操作でも同じテーブルを作成できる。本開発でリモートD1へSQLを実行しない。
- 旧「確認済み」フラグやクライアントからの `approved` / `stage` は新しい全文確認の代わりにならない。
- 本文だけでなく資料・対象読者・条件・企画・構成を保存し直すと新しい版になる。前の版の全文確認を自動継承しない。旧版の確認記録は残す。
- 古い版の保存・確認・出力要求は409で拒否する。確認のINSERTにも最新の版を条件として付け、読み込み後の同時編集を検出する。
- 未保存の変更がある画面では全文確認・出力を停止する。別案件を開く前にも制作案件または端末への保存を促す。別案件として準備するときは現在の本文を保持し、IDだけを新しくする。
- 既存の一般保存・有料保存・クラウド生成でも、登録済みの制作メタデータを落とさない。有料原稿の一覧では、旧ミラーの古い本文に新しい版番号を付けず、実際の最新版を表示する。
- 長文生成後に上限を超えた場合は保存を拒否し、旧原稿を残す。生成した結果をrecoveryに返し、画面で保全できる。課金試行は既存上限に含まれ、自動再試行しない。
- 外部資料の更新を常時検知する機能ではない。保存した出典・日時のスナップショットを使う。新しい資料を取り込んだら新しい版として再確認する。

## API

- `GET /api/business/editorial`: 制作案件と進行・確認状況。`before` で次ページ。
- `GET ...?projectId=...`: 最新の案件一式と不足検査。
- `POST /api/business/editorial` の `action:save`: AIを使わず案件を保存。expectedRevision必須（新規は0）。
- 同 `action:approve`: 最新版と5項目の人間確認を記録。
- 同 `action:export`: 最新版の人間確認を検証し、原稿を返す。外部投稿はしない。
- 既存 `POST /api/business/jobs` の `useSavedDraft:true`: 保存版から章・続きを再開。案件ID・版・制作条件を照合し、古い版や条件変更をAI利用前に拒否する。

既存認証とD1バインディングを使用。新しいAPIキー・有料契約・予算設定の変更はない。実際に生成するには前回実装の予算と料金設定が必要。本開発では実モデルを呼ばない。
