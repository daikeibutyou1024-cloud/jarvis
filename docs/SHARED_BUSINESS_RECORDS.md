# 公開準備・共有収支と成果

開発ブランチのみ。外部投稿・AI生成・販売・請求取得は追加していない。認証後の操作は既存のJARVIS_DBを使用するため、PreviewとProductionのDB分離を確認してから実データで利用すること。今回はリモートDB設定・移行・利用者データを操作していない。

## 公開準備

1. CONTENTで案件を保存し、現在の版を全文確認する。未保存の編集がある場合は準備できない。
2. 公開準備パネルで本文・告知案を取得する。告知案は機械的に組み立てた未確認案であり、別途内容を確認する。
3. 利用者が自分のアカウントで公開した後、URL・公開日・媒体を入力する。アカウント・規約・内容の3項目と手動公開を確認して記録する。

準備は案件ID・版・内容ハッシュに結びつく。別タブなどで原稿や確認状態が変わると記録を拒否する。公開記録は利用者の申告であり、公開先の存在・所有者・成果を検証していない。取消・復元は司令室内の記録だけに作用し、外部の記事を操作しない。

## 共有の収支・成果

収支は日付・案件（任意）・売上/経費/API費用・円金額・摘要。成果は案件・対象月・計測元・アクセス/クリック/成果件数。同じ案件・月・計測元は同じ記録となるため、変更時は先に現行版を取得する。計測条件がクリック由来の成果と異なる資料は、そのまま変換せず入力方法を判断する。

保存は期待する版を照合し、履歴と現行値を1トランザクションで更新する。競合は409で停止し、自動再試行しない。ブラウザは新規収支のIDを成功まで維持する。同じID・内容の新規保存の再送は重複しない。取消・復元も履歴を残す。表示履歴は最新100版、記録上限は1万件。

金額は小数2桁までの円の整数最小単位で保存する。他通貨を換算しない。入力差額は売上−経費−API費用で、実利益を意味しない。API費用を経費にも重ねて入力しない。USD建てAI利用台帳を混ぜない。未入力は未入力、母数0の率は未算出とする。記事別・全体・媒体別の重複範囲を足し合わせない。共有集計を読み込んだ場合のみ、その取得時刻と範囲を明記してAI部門の文脈へ渡す。日次レポートでも入力集計は実売上・実利益と分けて表示する。

## コピーと互換性

旧localStorageのjarvis_business_ledger_v2とjarvis_business_metrics_v2を変更・削除しない。旧画面の入力も残る。コピー元と共有先は自動同期されない。

旧端末コピー・CSV・JSONはプレビュー後に明示適用する。1回10件を原子的に保存し、1000件まで順番に処理する。途中停止時はそれ以前の10件単位は保存済み。再度同じファイルを取り込むと同じ内容の受付票を返し、重複しない。同じIDが異なる内容なら停止する。元の旧IDがない行も同内容の出現数ごとに安定IDを作る。コピー後に変更したデータの統合は自動で行わない。

CSVは1MB以下、UTF-8、ヘッダー必須。列順は変更可。未入力の計測値を0にしない。

- 収支: `id,date,type,amount,memo,projectId`。idは80文字以内の英数字・ハイフン・アンダースコアで必須。typeはrevenue/expense/api。dateはYYYY-MM-DD。
- 成果: `period,channel,visits,clicks,conversions,projectId`。periodはYYYY-MM。channelはall/note/x/instagram/tiktok/affiliate/other/unspecified。

JSON出力はjarvis-business-copy-v1形式。現行の収支・成果と取消状態をコピーするためのもので、全履歴・公開記録・設定・DBの完全バックアップではない。ページ間の同時更新を止めないため時点の原子性もない。新環境へのコピー後の版は1から始まる。案件付きデータは対象案件が既に存在する場合のみ取り込める。
