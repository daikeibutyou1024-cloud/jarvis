# 最小試作版A（模擬検証版）

対象は feature/ai-business-rebuild。定期収集・自動投稿は追加/有効化しない。

## 操作

1. RESEARCHの制作ガイドから情報源とキーワードを選び取得する。
2. 出典・取得日時・内容を確認し、資料を利用者確認済みにして選択する。取得だけでは確認済みにしない。
3. 制作ブリーフのテーマを入力し企画を提案する（実環境では有料AI）。全評価はAI仮説。
4. 採用企画の「この企画と確認済み資料でCONTENTへ」を選ぶ。未保存原稿があれば先に保存する。
5. 「現在のRESEARCH資料・企画を取り込む」で資料/企画を取り込み、構成を確認する。
6. 「AIで作成＋クラウド保存」を1回だけ実行する（実環境では有料AIとDB書込）。通常生成なら、後で制作案件を保存する。
7. 保存版から再開して案件・版・本文・出典を照合する。

ガイドは操作場所への移動だけを行い、生成・保存・再試行を自動実行しない。未完成原稿の保存・再読込もAの保存確認には含むが、完成/品質/人間の承認とは別。公開は手動。

## 原稿保護と失敗

保存競合等で返った救出本文は元原稿に結合せず別欄へ追記する。コピーして退避できるが、それ自体は保存ではない。既存の原稿・確認状態を置き換えない。未保存編集がある間は新企画の引き継ぎを停止する。

最後の結果/診断IDは現在の画面に表示する。ガイド自体は新たなDB履歴を作らない。ページを開き直すと再読込照合は再実施する。失敗の診断ログは既存のサーバーログに出力され、ログ保持期間は運用環境依存。

## 無料検証

- `npm test`: 取得→未確認拒否→確認→企画→生成→保存→再読込→版追加、およびタイムアウト・予算不足・保存競合・不正応答・進行状態。
- `npm run test:prototype-browser`: 同じUIと実APIハンドラー/使い捨てSQLiteで一連操作、失敗時原稿保護を確認する。外部取得とAIは固定の模擬応答のみ。許可外URLは遮断する。
- `npm run test:release-http` / `npm run test:release-browser`: 既存の無料/有料記事の回帰検証。

実AI、実Preview DB、外部取得先の現在の応答、Safari実機は未検証。実環境検証は別途承認が必要。予算・回数・出力上限・自動再試行禁止は維持。
