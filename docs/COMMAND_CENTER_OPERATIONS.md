# AI副業司令室: Preview内部ジョブ

今回: 手動起動のみ、Previewモックのみ。実AI、Cron、予約投稿、外部サービス書き込みなし。
案件IDとジョブIDを共有し、公開情報→記事→SNS案→登録済み成果→登録済み収支→承認待ちを処理する。
Web Locksで実行を直列化。同じ出典URL・公開日時は既存案件を再利用する。
処理段階と取得情報を端末保存し、失敗・中断後は本人が再試行する。暗黙の再送はしない。
端末保存なのでブラウザを閉じた後の実行・複数端末同期はしない。既存データを移行・削除しない。

承認と差し戻し、修正依頼は案件IDに記録。修正は旧版を保持し承認を解除する。
モックの自動修正は「タイトル：...」「追記：...」だけ。それ以外は依頼中として保存する。
人間が編集して保存した場合は再承認待ち。外部への公開は承認済みでも行わない。

## セッション
既存パスワードをサーバーで確認し、8時間の署名付きCookieを発行する。
HttpOnly / Secure / SameSite=Strict / __Host-接頭辞 / ホスト単位。
署名は既存の管理秘密から導出し、パスワード値は返さず保存しない。
API側は署名・期限・対象ホスト・ブランチを検証し、既存の認証処理へサーバー内で受け渡す。
書き込み要求は同一Origin必須。実AIの課金ガードはそのまま。
ホストが違う固定Preview URLへはCookieを共有しない。通常はブランチエイリアスを使う。
ログアウトは現在のブラウザのCookieを破棄する。他端末の一括失効やセッション一覧は未実装。
端末内データは従来のlocalStorageにあり暗号化しない。ブラウザプロファイルを共有しない。
Cookieセッションは既存秘密に依存するため、秘密変更時は失効する。
