# RESEARCH: 公開情報からの記事候補

既存の収集API /api/research/collect とRESEARCHの資料カード・人間の確認操作・端末保存を再利用する。
追加情報源は Ollama プロジェクトの公式公開Atom https://github.com/ollama/ollama/releases.atom 。
AIツールの更新を、AI活用の記事候補として扱う。副業の収益実績や成功例を生成しない。
公開されているフィードの最大60項目から日時が有効で未来でないものを新しい順に最大5件返す。
RC版も含むのでリリースURLと概要を人間が確認する。概要は配信元の内容の抜粋で、AIによる要約や翻訳ではない。
公開日時が不正な項目は除外する。5件に満たなければ取得件数のまま表示し架空情報で埋めない。

認証は既存の管理パスワード方式のまま。任意URLは受け付けず、固定URLだけをGETする。
認証ヘッダーを提供元へ転送しない。リダイレクト禁止、8秒、1MB制限。
新しい公式候補はCloudflare Cache APIで成功1時間・失敗5分の短期キャッシュを使う。
Cloudflareキャッシュは拠点単位で、全拠点共通の厳密な回数制限ではない。認証・手動送信・最大1配信取得で負荷を限定する。
D1にはアクセスせず、スキーマ変更・マイグレーション・初期化は不要。automation_*にも触れない。
候補一覧は既存の端末ローカル保存を利用する。従来の他情報源のD1処理は変更しない。
失敗時は未取得と理由を表示し、過去資料を今回の成功と扱わない。
URLで重複を除外し、既存カードも出典URLで更新する。人間の確認・CONTENTへの引き継ぎは従来どおり。

## Preview確認

1. 新しいPreview URLでRESEARCHを開く。
2. 「AI活用の記事候補5件（Ollama公式）」を選ぶ。キーワード欄はこの情報源では使用しない。
3. 本人が既存管理パスワードを入力し、「無料の情報源から取得」を1回押す。
4. 最大5件のタイトル・配信元の概要・出典URL・公開日時・取得日時・情報源を確認する。
5. 再取得ではキャッシュと重複抑止を確認する。実記事の作成・AI実行は不要。

モック有効化フラグはfalseを維持。Cron・新規契約・有料AI・自動投稿は使用しない。

## ローカル検証

- npm test：外部通信を禁止した回帰テスト。
- NODE_USE_ENV_PROXY=1 CODEX_PRIMARY_RUNTIME_NODE_MODULES=/workspace/jarvis-tools/node_modules node tests/research-candidates-browser.mjs
  実公式フィードを取得し、ローカルの一時認証・ブラウザで5件表示、再取得、端末保存、失敗表示を確認する。実D1・有料AIは使用しない。

Preview上で認証後の取得を行うには、本人の既存管理パスワード入力が必要。
Codexはパスワードの抽出や認証回避を行わない。ローカル検証をPreview認証後の実行済みと扱わない。
