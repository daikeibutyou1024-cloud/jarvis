# 案件別の月次振り返り

公開の申告記録、成果の計測値、円の収支を別々に確認していた状態から、対象月・案件ごとにまとめて確認できるようにした。外部の実績取得やAI評価を実装済みとは扱わない。

## 操作

司令室の「案件別の月次振り返り」で対象月を選び、「月次の記録を取得（AI利用なし）」を押す。既存認証が必要。25件ずつ表示し、続きは「次の25件」。対象月を変えたら先頭から取得し直す。画面を開くだけでは要求しない。

GET /api/business/monthly-report?period=YYYY-MM。afterは返されたnextCursorのみを使う。応答はno-store。読取専用で、テーブル作成・旧データの取込・中断ジョブ整理・AI・外部通信・投稿・送信・定期起動はしない。

## 対象と集計の意味

- 版管理テーブルdocument_revisionsの案件と、対象月に有効なbusiness_recordsに登場する案件を表示する。案件数が多い場合も25件ずつ取得する。旧business_jobsだけの下書きや端末内だけの記録は含まない。
- 名称と版は現在の保存状態。過去月の当時の案件名・版を復元する機能ではない。版管理側に名前がない記録も落とさず「名称は未取得」として表示する。
- 案件IDのない共有記録は「案件未指定の記録」として別に表示する。全体の計測、案件別、媒体別を自動で合算しない。
- 円の有効な収支だけを、売上・経費・API費用に分けて集計する。入力差額は売上−経費−API費用であり実利益ではない。USDのAI利用台帳は加算しない。円以外の通貨は換算せず除外件数を表示する。
- 収支の記録がなければnull・未入力。経費等が0と表示されても、入力されている記録の内訳に限る。月全体の経費がないことを保証しない。
- 成果は案件・対象月・計測元ごとのアクセス/クリック/成果件数。明示入力された0は0、記録自体がない場合は未入力。母数0のCTR・成果率は未算出。計測元ごとの範囲が異なるので合算しない。
- 公開記録はその月に手動公開したという申告記録の件数。外部未確認であり、実際の公開記事数・売上・販売件数を意味しない。同じ記事の別媒体・別版の申告も別記録として数える。記録なしでも未公開とは断定しない。
- 取消済みの記録は除く。日付は入力した日本時間の日付文字列の対象月を使う。自動取得時刻やUTCのAI利用枠とは区別する。
- 未入力の確認や、クリックがあって成果0件の計測元の条件・導線確認など、入力値に基づく確認事項を表示する。AIの評価・収益予測・自動での公開判断ではない。

現在有効な記録の複数回の読取に基づくため、完全に同一時点のスナップショットではない。確認時刻と範囲を表示する。読取失敗時は古い結果を現在の集計として残さない。不正な円金額・計測値・同じ計測範囲の重複は、正しい集計として表示せず停止する。

## 互換性・テスト・残課題

スキーマ変更なし。既存の原稿、版履歴、公開記録、収支・成果記録、旧端末データ、バックアップは変更しない。新しい集計用の永続保存も作らない。

今回10件追加し、全204件の自動テストに成功。集計前後のDB一致、未入力と0の区別、通貨/案件/計測元の分離、月の境界・取消・25件超のページング、未作成DB、旧案件名のない記録、不正値拒否、認証、エラー時の非開示、画面の月変更・重複要求・古い結果消去を模擬SQLite/D1とDOMで検証した。未模擬fetchは遮断し、実Claude/OpenAI/外部収集を使っていない。

既存PlaywrightテストはChromium起動時のsocket() Operation not permittedにより本体未実行。実Previewの認証後の集計・保存・移行は未検証。D1分離・無料利用枠・実請求の確認、外部成果取得、定期配信・通知は別途必要。実利用前に追加料金が発生しない利用枠とPreviewの保存先を確認する。
